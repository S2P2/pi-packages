# Domain docs

## Layout

Single-context: root `GLOSSARY.md` and root `docs/adr/`,
shared across all workspace packages.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.

If these files do not exist, proceed silently. Domain-modeling
creates them lazily when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
Reconsider undefined concepts or note genuine gaps for domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, citing the ADR
and explaining why the decision may need reopening.
